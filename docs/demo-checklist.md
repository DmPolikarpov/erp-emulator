# Чек-лист показа (M8)

Перед показом демо проходят две разные проверки: **автоматическая** (её видно в
терминале) и **ручная** (её видит зритель). Этот файл — вторая, плюс список
команд для первой. Раздел 8
[roadmap](dairy-plant-roadmap.md#8-как-проверять) задаёт сценарии; здесь они
превращены в пункты с ожидаемым результатом и местом для отметки.

Журнал прогона — в конце файла. Скриншоты — `docs/demo-artifacts/`
(см. [README](demo-artifacts/README.md)); видео ссылкой, не файлом.

## 0. Окружение

| Проверка | Команда | Ожидаемо |
| --- | --- | --- |
| Кластер поднят | `kubectl get pods` | движок, шлюз, Postgres, NATS — `Running` |
| Шлюз доступен локально | `kubectl port-forward svc/bpmn-gateway 8080:8080` | `curl http://localhost:8080/api/v1/process/instances` отвечает 200 |
| Кабинет запущен | `npm start` в `erp-simulator` | `http://localhost:3000` открывается без оверлея ошибки |
| `.env` на месте | `type .env` | `REACT_APP_GATEWAY_URL`, `REACT_APP_WS_URL`, `REACT_APP_METRICS_API_URL` |
| Чистая БД (для показа «с нуля») | `wip/db-wipe.sql` через `kubectl exec … psql` | таблицы `process_instances`, `tokens`, `orders` пусты |

## 1. Автоматические проверки

```bash
cd erp-simulator
npm run test:ci                 # Jest: схема, кабинет, метрики
npm run sdk:verify              # артефакты SDK совпадают с исходниками
npm run build:verify            # production-сборка + маркеры демо в бандле
cd ..
tests/run-live-e2e.sh           # живые API: orders, roles, metrics, ws-filter
node wip/live-metrics-check.cjs # живой ответ /api/v1/metrics через CRA-прокси
```

`npm run build:check` отдельно проверяет, что в бандле есть три процесса демо,
роли кабинетов, кнопки участников, клиент метрик M7, и что сборка не старше
исходников ([`scripts/check-bundle.mjs`](../scripts/check-bundle.mjs)).

## 2. Сценарий A — контур завода (M0)

Вход: «Менеджер по продажам» → проект «Молочный завод: заказ → производство →
отгрузка» → «Задеплоить BPMN в Оркестратор».

| # | Шаг | Ожидаемо | ✓ |
| --- | --- | --- | --- |
| A1 | «Принять заказ клиента» | активный шаг `Task_RegisterOrder` | |
| A2 | «Зарегистрировать заказ в 1С:УТ» | шаг `Task_CheckLimit` | |
| A3 | «Проверить лимит и подтвердить сроки» | развилка остатков ГП | |
| A4 | «ГП не хватает — закупить сырьё» → вход «Менеджер по закупкам» → «Рассчитать потребность и создать заказ» | активный шаг у закупок | |
| A5 | «Согласовать в пределах лимита» → «Отправить заказ поставщику» | в журнале движка — старт процесса поставщика | |
| A6 | Вход «Менеджер по продажам сырья» → «Принять заказ на сырьё» → «Погрузить и передать перевозчику» | событие `milkShipped`, у завода оживает приёмка | |
| A7 | «Менеджер по закупкам»: «Подтверждение получено» → вход «Приёмка и лаборатория»: приёмка, склад сырья | шаги идут по дорожкам пула | |
| A8 | Производство: очистка → нормализация → гомогенизация → пастеризация → ферментация → контроль ТУ → розлив | после каждого нажатия подсвечен следующий узел | |
| A9 | «Скомплектовать, оформить УПД и ТТН» | узел отгрузки, процесс завода ждёт клиента/конец | |
